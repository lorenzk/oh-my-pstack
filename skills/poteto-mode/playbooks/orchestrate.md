### Orchestrate

**You run the program, never the code. Decide which agent does each piece of work, then check what each produces.** For a standing multi-day project with many PRs and few human turns. One task driven to a predicate is Autonomous run. One ambitious run needing a bespoke workflow is figure-it-out. Work one agent can finish inside the session's budget is not a program.

Use the active adapter's canonical protocols, not a bookkeeping CLI. Keep the goal, standing orders, unit states, branch and PR heads, session identifiers, verification receipts, and operator gates in a durable project tracker or `notes.md` in the host's store. If there is no store, name a project-local decision trail. Give every record one writer. Watch PR and CI events when the host supports subscriptions; otherwise use a root-started **One-shot watcher** with a bounded timeout and checkpoint on capability gaps. Do not create shell polling loops or invent a Project API, scheduler, or cloud runtime.

#### Topology

- **One owner per PR.** A root-started canonical `owner` is the only writer of its branch. It builds, pushes, rebases, and retargets only within its brief's authority, then reports merge-ready. The root owns approvals, integration, and authorized merges. Owners never merge or arm auto-merge. Closing or retargeting a base PR affects its descendants, so it needs the root's call. The coordinator never edits product code; conflicts, chain rebases, and fixes go to the assigned owner.
- **A fresh worker for each independent task.** Use **Bounded session** by default. Its standalone brief includes the user's goal, exact writable and forbidden paths, branch or worktree, configured model role, standing orders, acceptance evidence, and upstream reports it depends on. Writers get separate managed worktrees. Run checks where the required simulator, control tooling, or auth exists; report missing capabilities rather than claiming cloud execution.
- **A sub-coordinator only when one area has many parallel workers.** It proposes scoped briefs and sends one rollup to the root. Children never start children. The root dispatches every worker and verifier. Keep about ten workers in flight per coordinator and refill as results arrive rather than waiting on a whole batch.
- **Retain a session only for costly live state.** Start fresh with the consolidated brief and prior report otherwise. On Pi, use `pstack_followup` only for a completed owner's costly live-state exception. Never send a follow-up just to check liveness.
- **Each PR gets an independent verifier.** Use a configured model from a different family when available. If policy cannot provide one, report the gap rather than inventing a fallback or claiming model diversity. Accept only route-validated evidence for the current head. The root merges only under an explicit landing grant and a passing verdict.
- **Start with one unit.** Take it through kickoff, owner, verifier, and authorized merge or operator handoff before fanning out. A flaw in the brief should cost one agent, not fifty.

#### Supervision

- **Name the proof before dispatch.** Each brief names the exact command and expected result, real-surface check, or artifact proving completion. If the evidence cannot be named, the unit is not scoped.
- **Read the diff or artifact, not only a summary.** On Pi require `pstack_status` success with empty failure lists before acceptance. Green CI is an input, not a verdict. Behavioral work needs more than a type check. A new head needs a current verdict. Sample each sub-coordinator's briefs while work runs and fix its instructions when a brief fails.
- **Keep scope narrow.** Send drifting or oversized work back. Fix only what blocks the program and park the rest as follow-ups.
- **Check live PR state before reporting.** Use `gh pr view` and `gh pr checks`, or the active forge's equivalents. Record each head, base, verdict, and receipt path. Account for every worker as done, replaced, or absorbed into another scope.
- **Replace stalled work safely.** Judge progress by commits, pushes, PR activity, and durable artifacts, not status text or transcript timestamps. Retry with smaller scope after a context limit and the same brief after a dropped connection. Repair tool instructions after a tool error; changing a configured model needs approval. After two retries, drop the unit and replan. Stop and reconcile an old writer before assigning a replacement to the same branch or worktree. Reconcile late results against current state and hand unique findings to a fresh worker.
- **Ask only for a real decision or blocker.** Preserve operator gates and always-pause actions. Routine retries and CI triage stay with the root. On stop, send zero-writes orders and cancel scheduled work. After context loss, read the tracker and standing orders, reconcile sessions and branches, and continue only from durable evidence.

**Reply:** what landed against the user's goal, each PR's live state and current verdict with its link, dropped work and why, decisions waiting on the user, and the tracker and trail paths.
