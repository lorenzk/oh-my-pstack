### Autopilot-full

**You own the verdicts and merges, never the PR implementation. One owner carries each PR through merge-ready, and nothing lands until independent verification proves the code that lands.** Owners never delegate or merge. The root owns verification, countersigns, approvals, and authorized merges.

A verdict covers a patch; green CI covers a head. Run a full swarm once at code-ready, then scale repeat verification to the change. Every new head needs its own green CI and a current verdict or evidence that the earlier verdict survives the Shipping patch-id rule.

Resolve the forge once. Default to `gh`. If `command -v origin` succeeds and Origin resolves the repository, use `origin pr` and record any fallback. Never require Graphite. An installed PR tool takes precedence for supported operations, per **Opening a PR**.

1. **The operator's gates come first.** The grant covers only the queue. Operator-named items and PRs outside it stop at merge-ready. A request to state the plan is not a go. Execution starts only on explicit go.
2. **Start one owner per PR and externalize its work early.** Use canonical `owner` with the active playbook's configured model role. Start a fresh **Bounded session** each round with the consolidated brief, prior report, and exact branch. Use **Long-lived owner** only for the costly live-state exception. The owner builds, pushes its assigned branch, opens a ready PR early per **Opening a PR**, proves the real artifact, and reports merge-ready. Within about 15 minutes, push the first snapshot and start `decisions.tsv` in a durable host store or named project-local trail. Push every verifiable unit with hooks on. Keep receipts accessible to a replacement, not only in an ephemeral workspace.

   Finish **unslop** and root-started **no-comments** review before code-ready. Rebase onto current trunk, run required pre-review checks on the committed head, then report the code-ready SHA before self-proof so it can overlap verification. A hook pass is not proof. Report every later head. Fix rounds keep that base unless trunk conflicts, breaks CI, or lands a known concurrent change to the same files. An authorized force-push uses `--force-with-lease` pinned to the last pushed or explicitly taken-over remote SHA, never a shared branch. An unexpected remote push stops the owner for reconciliation. The root starts Babysit watchers and every other child and records IDs, generations, scope, state, and stuck-after runtime in `children.tsv`. Owners never delegate.
3. **Run owners in parallel off trunk, never stacked.** Give each writer a separate branch and worktree. Serialize genuinely overlapping writes. Independent PRs land independently. Dependent work goes merge-then-branch, unless the operator chose Autopilot-stack.
4. **Swarm-verify once, then verify what changed.** At code-ready, freeze the head and start independent verifiers through **swarm**. Run gates, a live lane on the real surface through an installed control capability or named driver, at least two diff-audit lanes with different focuses, and a regression lane against current trunk. If trunk lacks the feature, record that and gate the added behavior and user's end state. A verdict without the live lane is not clean. Audit merge-ready receipts yourself.

   Another full swarm is required for new behavior, a redesign, or a large new diff. A rebase, conflict resolution, or minor fix gets a single independent verifier at the new head. A wording-only change needs fresh checks and root review of the wording, not another verifier. Carry a prior lane result only under `skill://poteto-mode/playbooks/shipping.md`'s patch-id and build-equivalence rules. A failed or missing required lane remains a gap, never a pass.

   Block only for a demonstrated user-visible bug, failed gate, or shipped documentation made wrong. Require a failing run at the reviewed head or the exact wrong doc line. A pre-existing base bug does not block unless the PR copies it or newly reaches it; record it separately. Send proven findings in one fix-forward. For a behavior defect require a red test covering the same defect's sites, or a repro receipt, and add it to the next brief.
5. **Only the root squash-merges what was verified on the base it lands on.** Merge prep starts after the swarm lanes start. Rebase onto current trunk, record the new head, and require green CI. Immediately before merge, fetch trunk and require a clean `git merge-tree`. Rebase and wait for CI if a conflict, shared changed source path, or CI-selection change means the merge result was never tested. A shared lockfile can avoid a rebase only when a frozen install passes on an isolated merge result and the changed packages resolve as on the head. When trunk changed callers, callees, or dependency versions, run the patch's checks on that merge result. Preserve those receipts. Unrelated trunk movement alone does not force another rebase. If trunk would force a third rebase after merge prep, hold and let the root sequence the colliding work. Reconcile every rewritten head with step 4 and Shipping before landing. Green CI alone never authorizes a merge. Only the root squash-merges under the operator's landing grant and clean verdict; operator-named items wait for the operator. A fresh owner takes the next item.
6. **Run the root layer hourly.** Anything that loosens a gate, including a budget raise or allowlist entry, needs independent proof and a fresh root countersign within the operator's grant. Record it in the tool's allowed form with the approval evidence. Remove disabled or soft-failed checks rather than treating them as proof. Never bypass forge-enforced approvals.

   On go, schedule a real hourly audit through an installed scheduler. Native Pi has no built-in `/loop`; if none exists, record the gap and checkpoint rather than claim unattended wakes. Native completion notifications collect results; do not add polling or sleep loops. At each tick re-read this playbook from trunk if present there, otherwise from the installed package, plus the durable objective. Check every tracked owner and leaf lane by side effects and its trail. Fix unreported heads and missing records through their owner. An error, inability to start turns, or no progress beyond the stuck-after runtime is a stall; waiting on the root or operator is not. Stop and reconcile an old writer before replacing it in the same scope. A stall never proves or drops the work. Run retro and post-merge bot-comment sweeps after batches. Keep auditing until no delegated work remains. Log every tick; when something changed for the operator, catch them up through **ketchup**. Stay quiet on unchanged ticks.
7. **Stand down at once on the operator's stop.** Send every active child a zero-writes order, cancel scheduled work, and preserve briefs and checkpoints until released.

**Reply:** catch the operator up through **ketchup**, covering each PR's state and verdict, merges, countersigns and why, operator gates, parked follow-ups, and links to PRs and trails.
